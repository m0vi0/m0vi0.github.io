Resilient home network with automatic failover

Remote access and monitoring built around a router I had no admin access to.

  • Tailscale
  • Uptime Kuma
  • Wazuh
  • Failover

This started from a practical constraint: I had no admin access to the home router. Without router-level control (port forwarding or VLANs), I had to build remote access and monitoring without touching the network infrastructure itself.

Initial approach

First I put individual devices on a mesh VPN so I could reach them remotely without touching the router. I picked Tailscale for its low-friction WireGuard-based overlay: it creates encrypted connectivity between nodes quickly and needs no router changes for basic remote access.

Subnet routing for devices that can't run a client

Many home devices (smart home appliances, cameras, embedded controllers) can't run a VPN client. To reach those, I used subnet routing: one or more machines on the LAN advertise routes into the tailnet, so tailnet clients can reach LAN devices without direct access. Reachability stays intact and the physical router stays untouched.

Removing the single point of failure

One subnet router is a single point of failure. So that I don't lose remote access when a node goes down, I configured several nodes to advertise the same routes. Tailscale fails over between them automatically, and the tailnet keeps reaching the LAN through whichever subnet router is up.

Monitoring the monitors

Redundant routing only helps if someone notices a failure. To avoid making the monitoring itself a single point of failure, I run two Uptime Kuma instances. Each one checks the subnet routers and also watches the other monitor, so a blind spot in one gets caught by the other.

Security monitoring on top

Once the access layer was resilient, I layered security monitoring on top. Wazuh runs across the router nodes to collect host telemetry and correlate events. A Kismet instance on one node does wireless detection and forwards deauth alerts into Wazuh over syslog (writeup), and an object-detection camera (Frigate) adds physical detection signals. The goal was for remote access and monitoring to reinforce each other instead of being separate fragile systems.

Operational notes and limits

This works well when there are several reliable nodes, but it adds operational work: approving routes in the Tailscale admin console, keeping subnet routers patched and online, and making sure the monitors stay reachable. With router admin access, doing the routing at the router would be simpler. This design is a workaround for when that access isn't available.

What I learned

Build redundancy early and test failover: automatic failover is only useful if it's exercised and monitored. When I design for resilience now, I map failure modes across routing, monitoring, alerting and response, so a fix in one place doesn't open a blind spot in another.
